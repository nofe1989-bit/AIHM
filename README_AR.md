# بيانات Samsung Health: تنظيف الملف الجديد ودمجه مع السابق

## ابدؤوا بهذا الملف
`Combined_HR_5min.csv`: جدول التحليل المجمع، 6377 صفًا و21 عمودًا. كل صف يمثل نافذة خمس دقائق لمصدر وجهاز محددين، مع القراءات المتاحة فقط. الصف لا يعني أن الجهاز قاس بشكل مستمر طوال الخمس دقائق. الأعمدة تشمل بيانات القياس ومعرّفات المصدر والتوقيت وعلامات التوفر، وليست 21 قياسًا مستقلاً.

## الملفات المهمة
| الملف | وظيفته |
|---|---|
| Combined_HR_5min.csv | جدول التحليل المجمع؛ إحصاءات النبض والخطوات السابقة |
| Combined_HR_clean.csv | كل سجلات النبض من المصدرين: 8113 صفًا؛ يتضمن ملخصات الفترات |
| New_HR_clean.csv | الملف الجديد وحده بعد التجهيز: 6207 صفوف، مع علامات الفحص |
| data_dictionary.csv | معنى كل عمود ورمز ووحدته |
| EDA_Report.html | تقرير مبسط بالعدد والنتائج والقيود؛ يفتح بالمتصفح |
| merge_samsunghealth_hr.py | كود بايثون المستخدم لتنظيف الجديد وإضافته للسابق |
| requirements.txt | مكتبات بايثون اللازمة لتشغيل الكود |
| audit | نتائج الفحص وعدد السجلات يوميًا والملخصات التي تنقصها التفاصيل |
| inputs | نسخ المدخلات اللازمة لإعادة تشغيل الكود؛ ليست النتائج النهائية |

## ما الذي حدث بالخطوات؟
1. قرأنا ملف النبض الجديد؛ تجاهلنا سطر تعريف Samsung في البداية وضبطنا أسماء الأعمدة والنهايات الفارغة في الصفوف.
2. حوّلنا النبض إلى أرقام والتاريخ إلى صيغة قابلة للتحليل، وفحصنا أن نهاية القياس لا تسبق بدايته.
3. فحصنا التكرار والتعارض في معرفات السجلات. لم نجد صفوفًا مطابقة مكررة أو معرفات متعارضة في الجديد. معرفات المصدر الجديدة لا تتقاطع مع معرفات سجلات النبض الأصلية السابقة؛ هذا لا يثبت اختلاف الأشخاص أو استقلال العينات.
4. فحصنا النبض باستخدام معيار العمل السابق: من 30 إلى 220 نبضة في الدقيقة. نطاق الجديد 41–195؛ لم يستدعِ الفحص حذف أي قراءة جديدة. هذا فحص نطاق، وليس تأكيدًا طبيًا أو تأكيدًا لجودة الحساس.
5. فصلنا نوعي السجلات الجديدة: 5463 قراءة منفردة و744 ملخص فترة تشير إلى ملفات JSON غير مرفقة. حفظنا الملخصات ولم نخترع قراءاتها التفصيلية.
6. أضفنا 6207 سجلات جديدة إلى 1906 سجلات نبض سابقة: الإجمالي 8113. وحفظنا علامة المصدر والجهاز حتى لا تختلط الهوية بين المصدرين.
7. أعدنا جدول الخمس دقائق باستخدام القراءات المنفردة وتفاصيل الدقيقة الموجودة من المصدر السابق فقط: 7369 ملاحظة نبض مؤهلة. حسبنا المتوسط والوسيط وأقل وأعلى قيمة وتشتت القيم وعددها. لم نستخدم 744 ملخص فترة في إحصاءات الخمس دقائق لأنها تفتقد التفاصيل.
8. أبقينا بيانات الخطوات السابقة مرتبطة بمصدرها وجهازها. لا يحتوي الجديد على خطوات، لذلك تركنا خطواته فارغة. لم نعوض القيم المفقودة بصفر أو نملأ الفجوات.
9. راجعنا أن جدول المصدر السابق يطابق نتيجته السابقة، وأن مجموع النبض والخطوات محفوظ وعدد القراءات يطابق العد في جدول التحليل.

## الأرقام باختصار
- الجديد: 6207 سجلات على 129 يوم تسجيل متفرقًا بين 2025-11-04 و2026-10-06 بحسب تفسير التوقيت المستخدم.
- السابق: 1906 سجلات نبض مفصلة/منفردة.
- المجموع: 8113 سجل نبض؛ منها 744 ملخص فترة لا تتوفر ملفات تفاصيله.
- جدول الخمس دقائق: 6377 صفًا؛ 5461 للجديد و916 للسابق.
- 6177 نافذة فيها نبض، و201 نافذة فيها خطوات، ونافذة واحدة فقط فيها نبض وخطوات معًا من المصدر نفسه.
- زيادة العدد هنا تخص سجلات النبض؛ لا تثبت زيادة عدد المشاركات أو كفاية البيانات للبحث.

## التوقيت والجهاز ونطاق الدمج
- فُسّر وقت CSV الجديد على أنه UTC بنفس طريقة التصدير السابق، وأضيفت ثلاث ساعات للعرض المحلي وفق الحقل UTC+0300. لا توجد ملفات JSON الجديدة للتحقق المستقل من هذا التفسير؛ يؤخذ ذلك بالحسبان عند مقارنة التوقيت بمصدر خارجي.
- المصدر السابق معروف: Galaxy Watch4 Classic. الجديد يحتوي معرّف جهاز مختلفًا، لكنه لا يتضمن ملف device_profile.csv الذي يثبت نوع الجهاز؛ يبقى نوعه غير مؤكد. اختلاف معرف الجهاز لا يثبت اختلاف الشخص.
- الدمج الحالي يجمع سجلات المصدرين في جدول واحد مع هوية كل مصدر، ولا يلصق نبض الجديد بخطوات السابق عند تطابق الوقت.
- ملفا Figshare وZenodo منفصلان عن هذه الحزمة. هذه إضافة لبيانات Samsung Health الشخصية السابقة فقط. بقية جداول المصدر السابق، مثل النوم والتوتر، موجودة في حزمته السابقة ولم تتغير بهذا الملف الجديد.
- للحصول على تفاصيل 744 ملخصًا والتحقق من نوع الساعة، يلزم إرسال تصدير Samsung Health الكامل متضمنًا JSON وdevice_profile.csv.

## تشغيل الكود مجددًا
يتطلب Python 3.10 أو أحدث. افتح الطرفية داخل هذا المجلد:

```sh
python -m pip install -r requirements.txt
python merge_samsunghealth_hr.py --previous inputs/previous --new inputs/new_HR_source.csv --out regenerated_output
```

`audit/merge_audit.json` يسجل الأعداد وبصمة المصدر. الملف الفارغ `Combined_duplicate_rows.csv` يحتوي عناوين فقط لأن الفحص لم يجد تكرارات بالمفتاح المستخدم (المصدر والجهاز ومعرف السجل والتوقيت والنوع).

## معنى الرموز الأساسية
- HR: نبض القلب.
- bpm: نبضة في الدقيقة.
- CSV: جدول نصي يفتح ببرنامج Excel أو بايثون.
- JSON: ملف يحتوي تفاصيل القراءات داخل بعض ملخصات الفترات.
- EDA: فحص استكشافي لوصف البيانات وأعدادها وتوفرها.
- UTC: توقيت عالمي موحد؛ الوقت المحلي هنا UTC+3 وفق حقل التصدير.
- True / False: نعم / لا.
- spot: قراءة منفردة. minute_bin: تفاصيل دقيقة من المصدر السابق.
- interval_summary_missing_details: ملخص فترة ينقصه ملف التفاصيل.
- export_01: المصدر السابق. export_02: المصدر الجديد. device_id: رمز جهاز وليس رمز مشاركة.
